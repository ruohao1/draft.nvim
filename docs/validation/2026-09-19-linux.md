# Linux extraction validation — 2026-09-19

Validated with Neovim 0.12.4, Python 3.14.4, Bubblewrap 0.11.1, Git 2.53.0 and
tmux 3.6. Neovim 0.12+ is required; a nested-fixture PATH mistake exposed binary
string handling failures on system Neovim 0.11.6, and the public setup now refuses
that unsupported version before registering commands.

`python3 -I -B tests/run.py` passed **46/46 suites**. This includes native
identity/session/review/transport checks, an actual private tmux lifecycle with
fake agent processes, the Bubblewrap confinement fixture, staging/approval and
follow-up regressions, internal conversation modules, and standalone setup/state
tests. The install suite copies the plugin into a path containing spaces and
exercises it from an unrelated working directory, including real sibling helper
lookup, a separate controller fixture process, and Neovim help tags.

All suites were also exercised from a clean Git archive under a path containing
spaces. Two fixture-only failures exposed unescaped runtimepath commands. The
three related Python launchers now pass their runtime path through an explicit
environment variable; all three affected suites passed from the relocated archive
after correction. The cache suite now uses a space-containing install path by
default. Production helper resolution did not need changes.

The Python suites discovered 414 tests: 405 passed and nine expected opt-in
installed-OpenCode cases were skipped. The managed-OpenCode Lua suite additionally
skips its installed-binary artifact audit by default. That audit was run separately
with `tests/run.py --opencode /absolute/path/to/opencode ai_opencode_managed`
against OpenCode 1.18.30 and passed. No real provider/account request was made.

The reported ACP receive-before-begin edge case reproduced an AttributeError in
both receive and poll, including after close. New regressions first failed, then
passed after validation was moved before deadline access. The original poll/cancel
regression remains intact. This does not integrate a production conversation
controller, persistent chat, or a conversation UI.

All automated tests use disposable editor state and owned fixture processes.
The restricted execution sandbox masks ownership and blocks local sockets, so
confinement tests ran in the approved Linux environment with real ownership and
namespaces. Production permission and sandbox checks were not relaxed.

Publication checks cover Python syntax, shell syntax, Lua formatting, portable
documentation/help, selected-file inventory, executable bits, and focused scans
for credentials, personal paths, private issue references and runtime artifacts.
Original source hashes and modes were rechecked; the source checkout and live
Neovim configuration were not modified.

An independent extraction review found no critical issues. Its one material
finding was the fixture path quoting issue above, which was reproduced and fixed.

These results establish the extraction's tested Linux boundary. They do not
establish macOS/Windows support, full tmux 3.7 acceptance, live-provider behavior
for every backend, persistent conversations, or automatic crash recovery.
